# 博客写作规范

> 本文件是本站 markdown 文章格式的**唯一来源**。`HANDOVER.md` 只负责交接与运维，格式问题一律以本文为准。
> 新增/修改文章前先读一遍；不确定的写法照本文或 `npm run new` 生成的骨架来。

## 1. 文件与目录

1. **目录**：`src/content/blog/YYYY/MM/<slug>.md`，`YYYY` / `MM` 取**发布日期**。
2. **分类子目录**：专题文章放子目录，子目录名**首字母大写**（`Docker`、`SQL`），如 `src/content/blog/2026/08/Docker/`。已发布的目录名不再改动（会断链），新增专题沿用大写风格。
3. **文件名**：全小写 kebab-case 英文 slug，禁止中文、空格、日期前缀。
   同系列用统一后缀：教程 `*-guide.md`、排障 `*-fix.md`、系列前缀 `vmware-*`、`debian-*`、`fedora-*`。
4. **新建**：用 `npm run new -- <slug> "<标题>"` 生成骨架，不要手抄旧文章。

## 2. Front matter

固定 **5 个键**，顺序固定，YAML `---` 包裹，**字符串一律单引号**：

```yaml
---
title: 'VMware 双虚拟机隔离上网教程'
description: '双虚拟机隔离上网'
pubDate: '2026-08-26'
updatedDate: '2026-11-17'
tags: ['VMware', 'Network']
---
```

| 键 | 必填 | 规则 |
| --- | --- | --- |
| `title` | 是 | 与正文首句不重复；不带句号 |
| `description` | 是 | 一句话摘要，**不得照抄 `title`** |
| `pubDate` | 是 | `YYYY-MM-DD`，零填充，不写时间与时区 |
| `updatedDate` | 否 | 仅在**实际修改已发布文章**时写，且必须晚于 `pubDate`（schema 已校验）。不写则整个键省略，**不要写成注释占位** |
| `tags` | 是 | 行内数组，至少 1 个，元素字母序；取值见第 7 节受控词表 |

不引入 `draft` / `slug` / `categories` / `heroImage` 等键；需要时先改 `src/content.config.ts` 与本节。

## 3. 标题

1. **正文不出现 H1**，标题由 `BlogPost.astro` 渲染 front matter 的 `title`。
2. 层级从 `##` 开始，最深到 `####`，且只在确实需要二级细分时用。
3. **编号一律阿拉伯数字**，禁止中文序号（`一、`、`（一）`）。整篇择一使用下面两种写法：

   - 长文（章节本身也编号）：`## 1. 安装教程` → `### 1.1 准备工作` → `#### 1.1.1 细节`
   - 分组型长教程（章节只作分组，不编号）：`## 安装教程` → `### 1. 准备工作` → `#### 4.1 设置挂载点`

   同一篇内不得混用两种，也不得出现 `一、` 与 `1.` 并存。
4. **标题末尾不加标点**（包括句号、冒号、问号）。疑问式内容改写成名词短语（`### Chrome 不出现该问题的原因`）。
5. 不跳级（`##` 下直接跟 `####`）。
6. 不用整行加粗充当小标题 —— 需要小标题就编号成 `###` / `####`。

## 4. 代码块

1. 所有围栏都用反引号 ` ``` `，**必须带语言标记**，白名单：
   `bash` / `text` / `yml` / `nginx` / `json` / `javascript` / `dockerfile` / `sql` / `lua`
2. 命令用 `bash`；配置文件内容、GUI 步骤、端口表用 `text`。
3. **没有合适语言的一律写 `text`**，不留空围栏。
4. YAML 写 `yml`，不写 `yaml`；JavaScript 写 `javascript`，不写 `js`。
5. 长输出用代码块，不要贴成普通段落。

## 5. 行内与排版

1. **中英文、中文与数字之间加一个空格**：`安装 Docker 后`、`共 3 个文件`（URL、占位符、表格值除外）。
2. 路径、命令、端口、IP、软件名、配置项**一律用反引号包裹**：`/etc/fstab`、`8080`、`docker compose up -d`。
3. 加粗 `**文字**` 内部不留空格，且**只用于两类**：界面元素/菜单名（`**菜单路径**`）、警示词（`**注意**`）。普通句内强调不用加粗。
4. 无序列表统一 `-`；有序列表用 `1.` 递增；嵌套内容缩进 3 空格。
5. 句末补全中文句号 `。`；文件末尾留一个换行；不留行尾空格；行尾统一 LF（`.gitattributes` 已固定）。
6. 表格统一 `| 表头 | 表头 |` + `| --- | --- |`（管道两侧各一个空格）。
7. 引用块用于菜单路径、注意、前置条件：`> **菜单路径**：IP → Addresses → Add (+)`。引用块内不空行。
8. 水平分割线 `---` 仅在文首目录之后允许使用，正文中不用。

## 6. 图片与敏感信息

1. 截图放 `src/assets/`，命名要有意义（`vm-b-proxy-config.png`，不要 `image.png`）。
2. 正文用相对路径引用，从 `src/content/blog/YYYY/MM/` 出发需 **4 层 `../`**：
   `![B 虚拟机代理配置](../../../../assets/vm-b-proxy-config.png)`
   在子目录（如 `Docker/`）里需 5 层，`npm run build` 通过即正确。
3. 敏感信息一律占位符：服务器地址 `your_ip`、账号 `your_username`、密码 `your_password`。

## 7. 标签受控词表

新标签必须先登记到本表再使用；同一概念不得出现两种写法。软件/项目专有名词按官方写法，通用类别用首字母大写单数。

| 标签 | 含义 | 收录标准 |
| --- | --- | --- |
| `Browser` | 浏览器相关 | 浏览器行为、扩展、缓存问题 |
| `Docker` | 容器部署 | 用 docker / compose 部署服务 |
| `ImmortalWrt` | 软路由固件 | ImmortalWrt / OpenWrt 相关 |
| `Linux` | Linux 系统 | Debian、Fedora 等发行版通用操作 |
| `Network` | 网络 | 路由、DNS、代理、端口、穿透 |
| `Rime` | 输入法 | Rime 及其方案、词典 |
| `RouterOS` | 路由器系统 | MikroTik RouterOS |
| `SQL` | 数据库 | SQL 语法与查询优化 |
| `VMware` | 虚拟化 | VMware Workstation 相关 |

## 8. 结构与篇幅

1. **通用骨架**（教程类）：
   `## 1. 前置条件` → 实测环境 → 分步操作（每步一个 `##`）→ 验证方式 → 常见问题/小结。
2. **Docker 系列固定五步**：

   ```text
   ## 1. 创建文件夹
   ## 2. 开放服务器端口
   ## 3. 创建 docker-compose.yml 文件
   ## 4. 创建配置文件（如需）
   ## 5. 启动服务
   ## 6+ 后续配置 / 测试 / 客户端设置
   ```

3. 配置字段用「字段 / 值」两列表格。
4. 开场一段说明**这篇文章解决什么问题、适用环境**，不写"本文将介绍…"这类空话。
5. 篇幅不设硬上限，但一篇只解决一个主题；超过 8000 字符考虑拆分并互相链接。

## 9. 检查与提交

- 本地：`npm run check`（Astro 类型）+ `npm run lint:md`（markdown 规范）+ `npm run build`（路由生成）。
- `npm run fix:md` 可自动修可修复项；`npm run fmt:frontmatter` 统一 front matter 引号、键顺序、标签排序。
- 提交前 `simple-git-hooks` 会对**改动过的 md** 自动跑 `markdownlint-cli2 --fix`。
- push 后 CI 会跑全量 markdownlint 兜底，不通过则不部署。
