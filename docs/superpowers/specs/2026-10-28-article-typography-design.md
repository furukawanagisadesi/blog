# 文章页正文字号 / 排版调整（按通行建议）设计稿

- 日期：2026-10-28
- 范围：`src/styles/global.css` 的全局排版数值（只动竖排节奏与字号，不动布局宽度）
- 起因：用户反馈「字体太大、文章页显得笨重占地方」，希望按中文排版通行建议收敛。

## 意图与目标

让文章正文读起来更轻松、页面更不「笨重占地方」，同时把字号/行高/行长/段距拉回中文网络排版的通行舒适区间。

- 目标：正文字号、标题层级、段间距回到主流建议范围；整页视觉更轻。
- 非目标：不改正文列宽（仍 820px）、不改首页/标签列表布局、不动 Twikoo 评论、不改字体栈、不加新功能。

## 依据（通行建议）

- 中文正文字号 14–18px，16px 最常用，长文 16–18px。
- 中文行高 1.5–1.8（CJK 约 1.7 最佳；WCAG 2.1 下限 1.5）。
- 每行中文 30–45 字为宜；W3C《中文排版需求》横排行长 ≤48 字。
- 段间距接近一个行高（行高的 ~1–1.5 倍）。
- 桌面端标题量级参考：H1 32–48px、H2 24–32px、H3 20–24px。

## 具体改动（`src/styles/global.css`）

`body` 字号 20px → **18px**（行高保持 1.7；20→18 后行盒变矮，已明显减负）。行宽仍 820px，18px 时约 **45 字/行**，在 W3C ≤48 内，故不改列宽。

| 元素 | 现在 | 改为 | 换算 (≈) | 对应建议 |
|---|---|---|---|---|
| body | 20px / 1.7 | **18px / 1.7** | — | 长文 16–18px，行高 1.7 |
| h1 | 3.052em (61px) | **2.0em** | 36px | H1 32–48px |
| h2 | 2.441em (48.8px) | **1.5em** | 27px | H2 24–32px |
| h3 | 1.953em (39px) | **1.25em** | 22.5px | H3 20–24px |
| h4 | 1.563em (31.3px) | **1.1em** | 19.8px | ≈正文上浮 |
| h5 | 1.25em (25px) | **1.0em** | 18px | 小标题 |
| `.prose p` 下边距 | 2em | **1.3em** | ≈23px | 段距接近行高（行高 30.6px） |
| blockquote | 1.333em | **1.1em** | ≈20px | 引用不喧宾夺主 |
| ≤720px body | 18px | **17px** | — | 移动端 16–17px |

不动：`h2~h6` 的 `margin-top: 1.5em`、`--content-width/--list-width`、`main` 宽度、字体栈。

## 取舍（Approaches）

- **A 温和收敛**（18px / 1.75 / 标题一档降）与 **C 更紧凑**（17px / 1.7 / 更小标题）二选一，是上一轮给的选项。
- 用户选择「按通行建议为标准」，因此采用本稿数值：正文取 **18px**（长文舒适档），标题压到桌面端通行量级，行高/行长沿用中文最安全的 1.7 与 ≤48 字。属于 A 的从容基调、但标题按通行量级收敛。
- 若之后仍觉偏大，可再把 body 降到 17px（一行代码），布局不受影响。

## 风险

纯数值调整，无结构改动，风险低。唯一需注意：标题变小后整体观感变「轻」，属预期效果；`h2~h6 margin-top` 未改，标题上下留白比例会略变，如看着偏大再微调。

## 验证

1. `npm run build` 通过（应为 29 页）。
2. dev + 浏览器核对文章页：正文约 18px、行高 1.7、约 45 字/行；标题层级明显小于旧版；段距更紧凑；390px 移动端无横向溢出、正文 17px。
3. 无回归：首页/标签列表布局不变，评论区不受影响。
